# 21 全链路重启与测试准备记录

## 1. 文档目的

本记录用于沉淀一次完整的“测试前全链路重启”操作，目的是将后端服务、消息消费链路和 Flutter 前端调试实例统一拉回到一个干净状态，避免旧运行实例和缓存状态影响测试结论。

## 2. 触发背景

在前端结果页已完成多轮优化后，用户仍然反馈页面效果与预期不一致。为了避免继续在不确定运行态上判断问题，本轮决定直接重启全部链路，再由用户基于同一组新实例重新测试。

## 3. 重启目标

1. 清理旧的 agent、business、inference 运行实例。
2. 清理旧的 Flutter web-server 调试实例。
3. 重新启动后端服务，并确认健康检查全绿。
4. 重新启动前端 web-server，并固定在 57717 端口，便于用户访问。

## 4. 执行动作

### 4.1 停止现有后端链路

执行 `scripts/dev-down.ps1`，并额外清理潜在残留进程，避免旧的 Python `main.py` 进程继续占用链路资源。

### 4.2 重启后端托管服务

执行 `scripts/dev-up.ps1`，重新启动：

1. inference 服务
2. business 服务
3. agent 服务

### 4.3 验证后端健康状态

执行 `scripts/dev-health.ps1`，确认以下检查项均通过：

1. 8001 端口可访问
2. 8080 端口可访问
3. inference `/health` 正常
4. business `/api/v1/diet-logs` 正常
5. RabbitMQ task consumer 数量为 1

### 4.4 重启 Flutter web-server

使用仓库内 Flutter SDK 重新启动前端调试实例：

1. 先清理 57717 端口残留监听
2. 再执行 `flutter run -d web-server --web-hostname 127.0.0.1 --web-port 57717`

最终前端页面服务地址恢复为：

1. `http://127.0.0.1:57717`

## 5. 当前结果

本轮重启后，后端链路与前端调试实例均已重新拉起：

1. inference、business、agent 已重启
2. RabbitMQ consumer 状态恢复正常
3. Flutter web-server 已重新监听在 57717 端口

## 6. 测试建议

为了确保本轮测试命中的是新实例，建议：

1. 直接重新打开 `http://127.0.0.1:57717`
2. 使用强制刷新或无痕窗口测试，减少旧资源缓存干扰
3. 测试时优先观察“可点击分割区域”下是否出现最新的轻量轮廓模式标记和更新后的徽标样式

## 7. 工程结论

在前后端联调阶段，当视觉效果与代码逻辑不一致时，完整重启链路是一种非常有效的基准化动作。它的价值不只是“让服务重新启动”，更重要的是统一测试前提，避免在旧实例、旧缓存和旧调试态上继续做无效判断。
