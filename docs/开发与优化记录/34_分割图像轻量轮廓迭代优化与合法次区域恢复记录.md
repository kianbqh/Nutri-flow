# 34 分割图像轻量轮廓迭代优化与合法次区域恢复记录

## 1. 文档目的

本记录用于沉淀本轮结果页分割图像展示优化的完整过程，重点说明：

1. 用户为什么会继续觉得分割图像“不清楚”。
2. 本轮前端层面做了哪些分步优化。
3. 为什么中途会出现“碎片少了，但合法区域也被误删”的回归。
4. 最终为什么改成“保留外边界、过滤内部孔洞”的方案。

## 2. 触发背景

本轮用户反馈的重点不是后端分割结果本身，而是前端展示效果仍然影响观感和辨识：

1. 区域与区域之间的分界不够清楚。
2. 某些类别边界过于碎片化。
3. 区域编号透明度偏高，阅读成本高。
4. 在第一轮优化后，虽然线条风格已经被用户接受，但残余小碎片仍然存在。

因此，本轮目标不是改推理链路，而是继续压缩展示噪声，同时保住已经被用户认可的线条粗细和整体风格。

## 3. 问题拆解

### 3.1 视觉可读性偏弱

结果页轻量轮廓模式的初始版本存在以下展示层问题：

1. 填充透明度偏低，区域主体不够显眼。
2. 轮廓白边和强调色边界偏弱，区域分界不够立。
3. 数字 badge 透明度偏高且尺寸偏小，编号辨识度不足。
4. 平滑处理较重，边界在一些区域上显得发虚。

### 3.2 碎片并不只来自连通域层面

前端已经在 `_compactMaskForDisplay` 中对类别并集 mask 做了展示层连通域压缩，但实际仍能看到残余碎片，说明问题不只在 mask 级别，还在轮廓构建级别：

1. 同一类别的展示 mask 虽然已做压缩。
2. 但 `_buildMaskBorderPath` 仍会把压缩后 mask 中的多个 boundary loop 全部绘制出来。
3. 这些 loop 里既包含合法的独立区域外边界，也包含内部小孔洞和锯齿碎环。

### 3.3 第一次“去碎片”方案为什么会误伤

本轮中途曾尝试按 loop 面积排序，只保留最大的 1 到 2 个 loop。这个方案确实能减少小碎片，但随后用户反馈：像右上角番茄这样的原本合法区域也消失了。

根因是：

1. 同一类别在前端会先被合并为一个 group mask。
2. 一个 group mask 内可以天然包含多个真实独立食物块。
3. 这些合法副区域在轮廓层面也会表现为次级外边界 loop。
4. 单纯按面积裁掉“次级 loop”，会把合法副区域和噪声碎环一起删掉。

因此，问题不是数据丢了，而是轮廓筛选维度选错了。

## 4. 本轮优化步骤

### 4.1 第一步：增强轮廓与编号可读性

先对 `nutri-mobile/lib/pages/result_page.dart` 中的 `_SegmentationOverlayPainter` 做了直接的视觉增强：

1. 提高非选中和选中区域的填充可见度。
2. 加强白色主轮廓和强调色辅轮廓。
3. 保留选中状态发光描边。
4. 提高 badge 底色不透明度。
5. 提高数字颜色对比度，并放大编号显示。

这一步解决的是“看不清”和“编号不醒目”的问题。

### 4.2 第二步：减少过度平滑造成的边界发虚

在 `_buildMaskBorderPath` 对轮廓点做平滑时，将迭代次数收紧到更保守的级别，避免边缘过度圆滑后显得模糊。

这一步的目标不是让边缘更细，而是让现有边界更利落。

### 4.3 第三步：保留展示层连通域压缩

`_compactMaskForDisplay` 继续保留对 mask 的 8 邻域连通域分析与展示层组件筛选，其职责仍然是：

1. 优先保留主要连通域。
2. 抑制极小离散碎片。
3. 只影响前端展示，不改后端推理结果。

这一步仍然是主轮廓收敛的第一道过滤。

### 4.4 第四步：第一次轮廓级抑制尝试

为继续消灭残余碎环，本轮一度在 `_buildMaskBorderPath` 中加入了“按 loop 面积排序，仅绘制最大几个 loop”的逻辑。

该方案的直接效果是：

1. 小碎片明显减少。
2. 用户也确认线条观感已经比之前好很多。

但它同时带来副作用：

1. 合法的次区域外边界也被误判为应删除的小 loop。
2. 右上角番茄这类原本正确的区域出现消失。

因此，这一版被确认不能作为最终方案。

### 4.5 第五步：最终改为“保留外边界、过滤内部孔洞”

最终版本不再按 loop 面积硬裁，而是改成基于有符号面积判断边界方向：

1. 为每个 boundary loop 计算 `signedArea`。
2. 以最大外边界 loop 的方向作为外边界基准。
3. 仅绘制方向一致的外边界 loop。
4. 过滤方向相反的内部孔洞与内部碎环。

这样做的结果是：

1. 同一类别里多个真实独立区域的外轮廓可以继续保留。
2. 内部噪声孔洞不会继续被绘制出来。
3. 不需要再用过激的面积阈值去硬裁合法区域。

## 6. 验证与发布动作

本轮每次关键调整后，都做了两类验证：

1. `flutter analyze lib/pages/result_page.dart`
2. 受管 Flutter web 前端重启，确保用户看到的是最新 bundle

受管前端地址保持为：

1. `http://127.0.0.1:57717`

同时也确认了一个运行态事实：

1. 如果用户看的不是 web 页面，而是本地 Flutter DEBUG 调试实例，那么仅重启 web 服务并不会同步更新该实例。
2. 这种情况下仍需对当前调试目标执行 hot restart。

## 7. 工程结论

这次优化说明，分割可视化的“碎片感”不能只靠更强的面积裁剪去处理。对当前结果页而言，更稳妥的做法是分两层控制：

1. mask 层用连通域压缩抑制离散碎片。
2. 轮廓层按边界属性保留真实外轮廓、移除内部噪声。

这样既能继续压制观感噪声，又不会把合法的小独立区域一起裁掉。
