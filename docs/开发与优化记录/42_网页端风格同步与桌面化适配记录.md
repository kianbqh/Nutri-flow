# 42 网页端风格同步与桌面化适配记录

## 1. 背景

在此前移动端整体风格统一之后，Nutri-flow 的移动端已经形成了比较明确的产品气质：

1. 暖色渐变主视觉。
2. 柔和白色 surface card。
3. 更偏产品化的标题、副标题与说明语气。
4. 结果页中对建议、分割区和摘要信息的分层表达。

但 `nutri-web` 仍然停留在较早期的白底表单和普通列表风格，导致：

1. 首页、上传页、历史页、目标页之间缺少统一视觉系统。
2. 网页端与移动端在产品感上明显割裂。
3. 上传结果页虽然能用，但更像调试界面而不是成熟产品页面。

因此，本轮目标不是把移动端界面逐像素复制到网页端，而是把移动端已经收敛出的视觉语言同步到 Web，并按桌面端使用习惯重新组织布局。

## 2. 本轮目标

本轮网页端同步聚焦三点：

1. 继承移动端的暖色卡片式产品语言。
2. 保留网页端自己的桌面化布局和阅读节奏，不做一比一照搬。
3. 不改原有业务接口与核心流程，只改前端展示骨架和页面结构。

## 3. 控制面判断

本轮首先确认了网页端样式的控制面：

1. `src/App.vue` 只提供了最薄的一层标题栏和全局背景。
2. `HomeView.vue`、`UploadView.vue`、`HistoryView.vue`、`ProfileView.vue` 各自维护 scoped 样式。
3. 业务逻辑较简单，界面风格主要由页面模板和样式层控制。

因此，最小可行方案不是重写业务逻辑，而是：

1. 在 `App.vue` 中建立全局视觉壳层和通用 token。
2. 对四个主视图做结构化重排。
3. 对 `MaskCanvas.vue` 做配套的视觉层更新。

## 4. 具体改动

### 4.1 全局壳层改造

在 `nutri-web/src/App.vue` 中完成：

1. 新增网页端品牌头部和四宫格主导航。
2. 把全局背景改为暖色渐变和柔和光斑，而不是平铺纯色底。
3. 抽出全局颜色变量、按钮样式、surface card、page hero、状态 pill 等通用类。
4. 统一输入框、下拉框和文本域的边框与焦点状态。

### 4.2 首页桌面化

在 `nutri-web/src/views/HomeView.vue` 中：

1. 将首页改为双列 hero 结构。
2. 左侧承载主标题与主要入口按钮。
3. 右侧以指标卡的方式概括识别主线、建议主线和网页端适配方向。
4. 下方新增功能卡、标准流程卡和设计原则说明卡。

这一步让首页不再只是简单欢迎页，而成为网页端整体产品风格的总入口。

### 4.3 上传页与结果区改造

在 `nutri-web/src/views/UploadView.vue` 中：

1. 将上传区重构为“预览主区 + 控制侧栏”的桌面布局。
2. 将拖拽上传、文件状态和拍摄建议整合为更强的视觉焦点。
3. 将餐次设置与分析说明放入独立控制卡。
4. 结果返回后，把总热量、识别项数量和建议状态先做摘要卡。
5. 将分割预览、识别明细表和饮食建议拆成独立卡片。

同时针对建议区做了产品化处理：

1. 增加 `splitAdvice()`。
2. 若建议文本首段为“个性化参考依据”，则单独拆到辅助说明卡中。
3. 主建议正文单独保留在更强调阅读体验的卡片里。

这一步与移动端结果页此前的产品化思路保持一致，但网页端改成了更适合大屏阅读的节奏。

### 4.4 历史页改造

在 `nutri-web/src/views/HistoryView.vue` 中：

1. 使用新的 hero 区表达“历史记录是后续建议上下文”的意义。
2. 将原先朴素列表改为更清晰的历史卡片。
3. 卡片中突出餐次、时间、状态、识别项数量和建议摘要。
4. 分页区改为独立卡片承载，减少按钮直接漂浮在页面底部的割裂感。

### 4.5 目标页改造

在 `nutri-web/src/views/ProfileView.vue` 中：

1. 将“目标设置”与“解释说明”拆成双列布局。
2. 左侧保留表单操作区。
3. 右侧补充目标如何影响热量判断、建议语气和饮食限制的解释卡。
4. 将当前目标、热量和限制数量提前放到 hero 指标区。

### 4.6 分割图组件配套调整

在 `nutri-web/src/components/MaskCanvas.vue` 中：

1. 调整画布背景和边框颜色。
2. 增强画布圆角和阴影层级。
3. 将图例改为更接近网页端新视觉体系的标签样式。

## 5. 设计原则

本轮最重要的约束是：

1. 风格同步，但不做移动端翻版。
2. 保留暖色渐变、柔和卡片和产品化文案。
3. 用网页端自己的顶部导航、双列布局、宽边距和模块化分区来承接这些元素。

因此最终结果更像“同一家产品的桌面工作台”，而不是“把手机页面横向拉宽”。

## 6. 涉及文件

本轮网页端风格同步涉及的核心文件包括：

1. `nutri-web/src/App.vue`
2. `nutri-web/src/views/HomeView.vue`
3. `nutri-web/src/views/UploadView.vue`
4. `nutri-web/src/views/HistoryView.vue`
5. `nutri-web/src/views/ProfileView.vue`
6. `nutri-web/src/components/MaskCanvas.vue`
7. `docs/开发与优化记录/42_网页端风格同步与桌面化适配记录.md`

## 7. 验证

本轮没有只停留在样式 diff，而是完成了两类验证：

1. `npm run build` 成功通过，说明新的全局壳层和页面改造未引入构建错误。
2. 通过本地 Vite 开发服务器实际检查了首页、上传页和目标页的页面结构，确认导航、hero、卡片层级和桌面布局已经按预期生效。

## 8. 结论

这次网页端同步的价值，不在于“把移动端照搬到 Web”，而在于：

1. 把移动端已经验证过的视觉语言延展到网页端。
2. 让网页端在产品感上终于和移动端属于同一套系统。
3. 同时保留网页端作为桌面工作台应有的阅读密度和结构节奏。
