# 46_移动端个人主页资料维护与助手分区优化记录

## 1. 背景

本轮调整来自移动端个人主页的直接体验反馈：

1. 页头仍保留“把账号、昵称和目标放到同一页维护，双端看起来才像同一个用户空间”这类解释型文案，不够产品化。
2. 昵称输入框附近没有明确保存动作，用户很难判断修改昵称后该点哪里。
3. 年龄、身高、体重、性别、活动水平等资料被放在“目标助手”区域里，但该区域底部只有“解析”相关按钮，容易让人误以为这些资料不会被保存。
4. 手动维护资料与 AI 交流解析混在一起，导致“资料填写”和“助手解析”两类动作语义不清。

## 2. 问题定位

问题集中在移动端个人主页文件：nutri-mobile/lib/pages/profile_page.dart。

原先页面结构虽然已经具备昵称、目标、基础信息和助手解析能力，但交互层面存在两个混淆点：

1. 页面把“手动维护个人资料”和“借助助手解析目标”揉在同一个连续流程里，导致用户无法快速建立心智模型。
2. 保存动作只出现在原“目标设置”卡片末尾，无法直观覆盖昵称与基础信息，尤其是年龄、身高、体重等字段位于助手区域时，保存边界更加模糊。

## 3. 本次修改

修改文件：nutri-mobile/lib/pages/profile_page.dart

### 3.1 调整页头文案

1. 删除“同一个用户空间”的解释型句子。
2. 改为更直接的用户表达，聚焦“维护昵称、基础信息和健康目标，让记录与建议更贴近你”。

### 3.2 重构为“资料维护区”

将所有需要手动填写和长期保存的内容集中到同一张资料卡里，并拆成三个明确子块：

1. 账号与昵称：展示当前账号摘要、昵称输入框、昵称建议，并新增“保存昵称”按钮。
2. 基础信息：收纳年龄、身高、体重、性别、活动水平，并新增“保存基础信息”按钮。
3. 健康目标与限制：保留目标、热量和饮食限制编辑能力，并将保存动作明确为“保存目标设置”。

这样处理后，用户不需要再猜测某个保存按钮到底影响哪一块资料。

### 3.3 独立“交流解析区”

将目标助手区改成单独的“交流解析”区域，只保留：

1. 文本/语音输入。
2. 当前会参考的基础信息说明。
3. “只解析建议”和“解析并写入资料”两个动作。
4. 解析结果摘要与错误提示。

同时移除年龄、身高、体重等手填字段，避免“资料填写”和“AI 解析”继续交叉在一个区块里。

### 3.4 修正按钮语义

1. 手动填写资料时，保存按钮跟随对应资料区出现。
2. 助手区明确区分“只解析，不改资料”和“解析后写入资料”两种行为。
3. 为避免状态更新后下拉框显示滞后，对目标、性别、活动水平控件补充了基于当前值的 Key，使程序化更新后 UI 能同步反映。

## 4. 验证

执行命令：

1. flutter analyze lib/pages/profile_page.dart

验证结果：

1. 页面分析通过，无 Flutter 静态检查错误。

## 5. 结果

本轮优化后，移动端个人主页的交互边界更清晰：

1. 手动维护资料统一落在“资料维护区”。
2. AI 交流解析单独落在“交流解析区”。
3. 昵称、基础信息、目标设置都具备更直观的保存入口。
4. 页面语言更像面向用户的正式产品页，而不是开发说明页。
