# 43_网页端账号绑定修正与个人资料体验优化记录

## 1. 背景

本轮处理聚焦两个直接影响体验和正确性的问题：

1. 网页端历史记录、上传分析和个人资料仍存在对默认演示账号的隐式回退，导致用户在未完成手机号验证时也可能看到 userId=1 的资料和历史记录。
2. 网页端部分文案仍带有“桌面化适配”“工作台”“开发叙事”等内部表达，不够像一个面向真实用户的产品页面。

同时，用户反馈 app 端没有明显看到“个人用户界面”，需要确认这是功能缺失还是旧运行态未刷新。

## 2. 问题定位

### 2.1 网页端账号串用根因

根因不在后端，而在网页端本地状态策略：

1. 上传链路此前会在本地没有账号时默认使用 userId=1。
2. 历史页和个人页此前也会在本地没有账号时直接回退到 userId=1。
3. 这种实现会让“未登录”被误解释为“读取演示账号”，从而出现手机号显示与历史记录归属不一致的问题。

### 2.2 app 端“看不到个人页”原因

排查结果表明，移动端个人资料页代码已经存在，问题主要来自运行态：

1. app 端首页本身存在 onboarding 和登录门槛，不会一上来直接落到个人页。
2. 旧浏览器页保留了旧 Flutter 运行态，表现为仍显示旧 onboarding 文案。
3. 重启并重新打开新页面后，已经能看到新版入口“先进入个人主页”，说明不是功能缺失，而是旧运行态没有刷新到最新代码。

## 3. 本次修改

### 3.1 收紧网页端账号会话

修改文件：nutri-web/src/api/dietLog.js

1. 新增网页端会话读写方法，统一管理 userId 和 authPhone。
2. 将“只有 userId、没有手机号”的旧残留状态视为无效会话，并自动清理本地缓存。
3. 上传接口改为必须具备完整手机号账号会话后才允许继续，不再默认回退到 userId=1。

### 3.2 历史页与上传页改为账号门槛模式

修改文件：

1. nutri-web/src/views/HistoryView.vue
2. nutri-web/src/views/UploadView.vue

处理内容：

1. 未验证手机号账号时，不再请求历史数据，也不会展示演示账号记录。
2. 未验证时，页面改为展示明确的引导态，提示用户先去个人资料页完成验证。
3. 上传页在未验证账号时禁用开始分析按钮，避免新记录被写入错误账号。

### 3.3 重做网页端个人资料页

修改文件：nutri-web/src/views/ProfileView.vue

处理内容：

1. 页面结构改为“手机号验证”与“资料设置”两段式。
2. 未验证状态下不再直接读取和展示默认演示账号资料。
3. 验证通过后才允许保存昵称、目标和饮食限制。
4. 增加切换账号入口，便于测试或更换手机号账号。
5. 默认昵称规则以产品说明形式明确展示：食迹用户 + 六位编号。

### 3.4 网页端产品文案去开发叙事

修改文件：

1. nutri-web/src/App.vue
2. nutri-web/src/views/HomeView.vue
3. nutri-web/src/views/UploadView.vue
4. nutri-web/src/views/HistoryView.vue
5. nutri-web/src/views/ProfileView.vue

处理目标：

1. 删除“桌面化适配”“工作台”“网页端同步原则”等偏研发过程的表达。
2. 改成用户收益导向，强调营养记录、热量估算、历史回看、个人目标和账号绑定。
3. 让首页、分析页、历史页、个人资料页在语气上更统一、更专业。

## 4. 运行态验证

### 4.1 网页端验证

1. 执行 nutri-web 的 npm run build，构建通过。
2. 打开 4173 端口运行页后确认：
   - 个人资料页默认展示“先验证手机号，再开始保存你的个人数据”。
   - 历史页未验证时只展示引导态，不再展示默认账号历史。
   - 上传页未验证时禁用分析入口，并明确要求先验证手机号账号。

### 4.2 app 端验证

1. 重启 Flutter web 运行态后，新开 57717 页面可见新版 onboarding。
2. 页面已经显示“先进入个人主页”按钮，而不是旧文案“先设置我的目标”。
3. 点击后会进入手机号登录 / 注册页，说明个人页入口链路是存在的，只是之前旧运行态没有刷新到最新代码。

## 5. 结论

本轮修改后：

1. 网页端不再把未登录状态误当作演示账号，历史记录、上传结果和个人资料只归属已验证手机号账号。
2. 网页端整体文案从“开发适配说明”收敛为“用户产品说明”，产品感和专业感更一致。
3. app 端个人页入口已经在最新运行态中恢复可见，用户若仍看到旧引导页面，应优先重新打开页面或做一次热重启 / 完整重启。
