# 40 结果页个性化建议展示优化记录

## 1. 背景

在上一轮 agent 个性化增强后，结果页中的 AI 建议已经能够稳定带出“个性化参考依据”，例如年龄、活动量、健康目标和近期饮食习惯等信号。

但移动端当前展示方式仍存在一个明显问题：

1. `result.adviceReport` 被直接整段渲染。
2. “个性化参考依据”与真正给用户看的饮食建议混在一块。
3. 整体阅读体验更像工程调试输出，而不是面向用户的产品化呈现。

因此，这一轮的目标不是改 agent 内容本身，而是把已有个性化信息重新组织成更自然的结果页表达。

## 2. 本轮目标

本轮结果页优化聚焦三点：

1. 保留“这次建议为什么这样给”的可解释性。
2. 降低“个性化参考依据”直接暴露时的工程感。
3. 让用户先看到可执行建议，再理解建议背后的参考来源。

## 3. 具体改动

本轮修改位于 `nutri-mobile/lib/pages/result_page.dart`，主要包括：

1. 将建议区标题从“AI 建议”调整为“饮食建议”。
2. 将副标题改为更产品化的表述：会结合本餐识别结果、目标和近期饮食情况整理建议。
3. 新增 `_splitAdviceSections()`，对 `adviceReport` 做轻量拆分：
   - 若首段以“个性化参考依据”开头，则提取为独立说明块。
   - 其余正文继续作为主建议内容展示。
4. 将“个性化参考依据”单独放到浅色辅助卡片里，并改成更自然的标题“这次建议主要参考”。
5. 主建议正文保留在原有强调卡片内，避免用户阅读顺序被解释性信息打断。

## 4. 结果

这次调整后，结果页中的个性化信息不再以“工程报文”的方式出现，而是被分成两层：

1. 上层说明用户这次建议参考了哪些因素。
2. 下层给出真正需要执行的饮食建议。

这样既保留了个性化透明度，也让页面更符合产品侧表达方式。

## 5. 验证

本轮完成后，对目标文件执行了错误检查，确认：

1. `nutri-mobile/lib/pages/result_page.dart` 未新增诊断错误。
2. 结果页拆分逻辑与新增辅助数据结构未引入静态错误。

## 6. 工程结论

个性化能力是否“被用户感知到”，不仅取决于 agent 有没有真的用到这些信号，也取决于结果页是否把这些信号以合适的方式展示出来。当前这次调整的价值，在于把“个性化可解释”从工程视角的直出文本，收敛成了更接近产品化的阅读结构。
