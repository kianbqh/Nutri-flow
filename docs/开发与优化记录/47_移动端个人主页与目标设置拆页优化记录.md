# 47_移动端个人主页与目标设置拆页优化记录

## 1. 背景

本轮调整来自移动端个人主页的进一步体验反馈，主要包括四个方向：

1. 默认昵称建议列表不够自然，用户更需要一个主流的“点击修改昵称后再编辑并保存”的交互。
2. 个人主页和目标设置混在同一页里，导致用户难以快速理解“这是管理账号昵称的地方”还是“这是设置健康目标的地方”。
3. 首页主模块更适合承接目标设置，因为这是分析建议最直接的前置入口；右上角则更适合作为个人主页入口。
4. 目标设置页需要更直观地服务“先说目标，再微调设置”的使用路径，因此语音输入应放在页面最上方。

## 2. 问题定位

问题集中在移动端以下几个入口与页面：

1. nutri-mobile/lib/pages/profile_page.dart
2. nutri-mobile/lib/main.dart
3. nutri-mobile/lib/pages/onboarding_page.dart
4. nutri-mobile/lib/pages/auth_page.dart

此前的实现虽然已经对个人页做过分区，但“个人主页”和“目标设置”仍然停留在同一路由中，造成两个直接问题：

1. 页面信息量偏大，用户进入后需要先判断自己当前是来改昵称还是来设目标。
2. 首页和 onboarding 虽然都强调目标的重要性，但真正的导航落点仍然是个人页，入口语义不够统一。

## 3. 本次修改

### 3.1 个人主页改为账号与昵称页

修改文件：nutri-mobile/lib/pages/profile_page.dart

处理内容：

1. 删除默认昵称建议列表。
2. 昵称区改为显示态 / 编辑态结构：
   - 默认只展示当前昵称与账号摘要。
   - 点击“设置昵称 / 修改昵称”后，才展开输入框与保存按钮。
   - 提供取消按钮，避免误编辑。
3. 个人主页不再承载目标设置表单，而是保留当前设置概览与“前往目标设置页”入口。

### 3.2 新增独立目标设置页

新增文件：nutri-mobile/lib/pages/goal_settings_page.dart

处理内容：

1. 新建独立“目标设置”页面。
2. 将语音输入放到页面最上方，先承接用户一句话描述目标的场景。
3. 将助手解析区和手动调整区放在同一页面内，但语义明确区分：
   - 上半部分：先说目标，支持语音 / 文本输入、解析建议、解析并写入本页设置。
   - 下半部分：手动调整基础信息、健康目标、热量和饮食限制，并统一保存。
4. 页面保留“本页设置会一起保存”的提示，减少按钮语义歧义。

### 3.3 首页主模块改为目标设置入口

修改文件：nutri-mobile/lib/main.dart

处理内容：

1. 右上角继续保留个人主页入口。
2. 首页主视觉区域中的次级主模块入口由“个人主页”改为“目标设置”。
3. 首页说明文案同步调整，明确右上角用于进入个人主页，主模块用于进入目标设置页。

### 3.4 onboarding 与登录后默认流转同步调整

修改文件：

1. nutri-mobile/lib/pages/onboarding_page.dart
2. nutri-mobile/lib/pages/auth_page.dart
3. nutri-mobile/lib/utils/navigation_utils.dart

处理内容：

1. 新增 RoutePaths.goals 路由。
2. onboarding 的推荐入口从“先进入个人主页”改为“先设置目标”。
3. 新用户登录成功后，如果原始目标是首页，则默认改为进入目标设置页，而不是个人主页。

## 4. 验证

执行命令：

1. flutter analyze lib/pages/profile_page.dart
2. flutter analyze lib/main.dart lib/pages/goal_settings_page.dart lib/pages/profile_page.dart lib/pages/onboarding_page.dart lib/pages/auth_page.dart lib/utils/navigation_utils.dart

验证结果：

1. 个人主页单文件分析通过。
2. 拆页后的关键移动端文件联合分析通过，无 Flutter 静态检查错误。

## 5. 结果

本轮调整后，移动端的信息结构与入口语义更清晰：

1. 个人主页专注于账号与昵称展示，不再承载大段目标设置表单。
2. 目标设置成为独立页面，语音输入位于顶部，更贴合真实使用顺序。
3. 首页主模块和 onboarding 的推荐路径都统一收敛到目标设置页。
4. 昵称编辑交互更接近主流产品习惯，只有在用户主动点击修改后才出现保存动作。

## 6. 后续收口

在本条记录完成后，又根据最新体验反馈补做了一轮轻量收口：

1. 删除目标设置页中“语音输入已经放在最上面”“写入本页设置”这类偏实现说明、偏开发视角的表达。
2. 将目标设置页主动作按钮从“解析并写入本页设置”收敛为更短的用户动作表达“应用到目标”，减少按钮视觉拥挤和换行风险。
3. 同步收敛个人主页页头说明文案，避免继续出现“模块已独立到某页”这一类结构解释。
