# 36 移动端整体风格润色与统一美化记录

## 1. 文档目的

本记录用于对本轮移动端 UI 润色工作做一次完整收口，重点说明：

1. 为什么首页做完之后，仍然需要继续统一其他页面风格。
2. 本轮移动端视觉系统是怎样抽出来的。
3. 各页面分别做了哪些结构与样式调整。
4. 为什么结果页只改页面骨架，不去破坏已经稳定的分割交互逻辑。

## 2. 触发背景

本轮移动端优化不是从零开始重做，而是由用户连续反馈逐步推动形成：

1. 首页最初过于单调、内容偏空。
2. 首页第一次扩展后又出现“有点臃肿”的问题。
3. 当首页风格被收敛下来后，其他页面仍然保留原先的普通表单或白底列表样式。
4. 结果是：应用虽然功能能跑通，但页面之间的视觉语言不一致，产品感不够完整。

因此，本轮目标不再是只修某一个页面，而是把整个移动端高频路径统一到同一套视觉系统中。

## 3. 本轮要解决的核心问题

### 3.1 页面之间视觉语言割裂

在本轮统一前，不同页面存在明显风格断层：

1. 首页已经开始有更明确的卡片和暖色氛围。
2. 登录、上传、历史、目标、结果等页面仍大量保留默认表单与列表结构。
3. 页面切换后容易给人“不是同一个产品”的感觉。

### 3.2 信息层级不稳定

旧页面普遍存在两个问题：

1. 标题、说明、操作区缺少稳定层级。
2. 重要信息和次级信息经常直接堆在同一层 ListView 里。

这会让页面虽然功能完整，但观感偏散，用户需要自己重新理解结构。

### 3.3 结果页不能为了美化牺牲现有交互稳定性

结果页在本轮之前已经完成多轮分割交互优化，包括：

1. 交互底图与 mask 空间对齐。
2. 主轮廓收敛与展示层碎片抑制。
3. 保留外边界、过滤内部孔洞。

因此，结果页这次只能统一页面外壳和信息区样式，不能再去动已经稳定的分割展示主逻辑。

## 4. 统一设计策略

### 4.1 先收敛视觉方向，再做页面批量迁移

本轮没有继续在每个页面里单独写样式，而是先确定一套统一的移动端视觉方向：

1. 整体采用暖色渐变和柔和光斑背景。
2. 主要信息区统一改成圆角白色 surface card。
3. 页面顶部统一使用带强调色渐变的 hero 卡片承接标题和引导文案。
4. 输入框、按钮、Chip、分隔线尽量由全局主题统一控制。

### 4.2 抽离共享页面骨架组件

为避免后续继续在每个页面里重复造样式，本轮新增共享组件文件：

1. `nutri-mobile/lib/widgets/app_chrome.dart`

其中沉淀出的核心组件包括：

1. `AppSoftBackground`：负责页面暖色背景与光斑氛围。
2. `AppSurfaceCard`：负责统一的白色圆角信息卡片。
3. `AppHeroCard`：负责页面头部主视觉。
4. `AppGlassChip`：负责 hero 上的玻璃感标签。
5. `AppSectionHeading`：负责各段落标题与辅助说明。
6. `AppHintStrip`：负责顶部或说明区的引导提示。

### 4.3 用全局 Theme 收口常规控件风格

除了共享组件，本轮还同步扩展了 `main.dart` 中的 `ThemeData`，统一以下控件表现：

1. `cardTheme`
2. `inputDecorationTheme`
3. `filledButtonTheme`
4. `outlinedButtonTheme`
5. `chipTheme`
6. `dividerTheme`

这样共享视觉系统不只体现在自定义卡片上，也能覆盖普通表单和按钮控件。

## 5. 页面落地结果

### 5.1 首页与整体入口层

首页已经在本轮前半段完成重构，并在用户反馈后继续收敛：

1. 去掉了重复且臃肿的“快速入口”区。
2. 把主要功能集成回顶部主模块。
3. 删掉无用语句，只保留面向用户的引导性内容。

这一步为后续所有页面提供了明确的主风格参照。

### 5.2 登录、引导与上传链路

以下页面已统一接入共享页面骨架：

1. `auth_page.dart`
2. `onboarding_page.dart`
3. `upload_page.dart`

这一段链路的目标是让用户从首次进入到开始上传分析，始终处在同一套视觉体验里，而不是在“营销页风格”和“开发页风格”之间来回切换。

### 5.3 处理中、历史与目标页

以下页面已完成统一化处理：

1. `processing_page.dart`
2. `history_page.dart`
3. `profile_page.dart`

其中：

1. 处理中页面将加载态、状态说明和操作按钮整合进统一信息卡。
2. 历史页把任务列表收敛为统一卡片式摘要，减少原始列表感。
3. 目标页把“目标设置”和“目标助手”拆为两张清晰的 surface card，改善信息密度与层级。

### 5.4 结果页的处理原则

结果页本轮的改动遵循“只统一页面骨架，不动核心交互逻辑”的原则：

1. 整体接入 `AppSoftBackground`。
2. 顶部图片、热量、状态、任务号、工作流信息统一收进主卡片。
3. 分割交互区、工作流路径、AI 建议都补上统一标题和卡片式容器。
4. 原有分割轮廓绘制、点击交互、区域详情逻辑保持不变。

这样既保证了结果页终于融入整体产品风格，也避免把此前已经打磨好的分割逻辑重新搅乱。

## 8. 工程结论

这次移动端整体润色说明，真正影响产品感的并不只是“某一个页面好不好看”，而是：

1. 页面之间是否共享同一套视觉语言。
2. 信息层级是否稳定。
3. 功能页是否也具备和首页一致的完成度。

本轮通过“共享样式骨架 + 全局主题收口 + 页面逐个迁移”的方式，已经把 Nutri-flow 移动端主链路页面统一到同一套暖色卡片式设计体系中，并且没有破坏现有分析、上传、历史、目标和结果展示功能。
