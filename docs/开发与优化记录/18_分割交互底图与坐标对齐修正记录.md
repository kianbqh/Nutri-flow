# 18 分割交互底图与坐标对齐修正记录

## 1. 文档目的

本记录用于说明一次非常关键但容易被误判的前端问题：用户看到“分割图几乎没变化”，并不代表代码没有生效，也不代表服务没有更新，而是交互底图选取策略本身存在偏差。

## 2. 问题现象

在上一轮已经调整了 Flutter painter 的轮廓颜色、填充透明度和默认选中策略后，用户反馈结果页看起来仍然和之前差不多，画面里依旧有明显的橙红色大块区域。

这类现象第一眼容易让人怀疑：

1. 前端热更新没有生效。
2. 服务没有重启。
3. 当前页面使用的仍然是旧版本代码。

## 3. 根因定位

经过对结果页与推理服务代码的联合检查，确认真正的根因不是部署，而是“底图来源”本身：

1. 移动端结果页默认优先使用 segmentation_preview_png_base64 作为交互底图。
2. 推理服务返回的 segmentation preview 在生成时就已经把前景区域叠加为红色半透明蒙层。
3. 因此，即使 Flutter painter 已经减轻了边界和选中态，用户仍然会先看到后端 baked-in 的红色预览图。

也就是说，问题不在“轮廓画得太重”这一层，而在“默认展示的底图本身就已经很重”。

## 4. 关键代码证据

### 4.1 移动端结果页

结果页此前使用如下策略：

1. 如果有 segmentationPreviewPngBase64，就优先作为 interactiveBaseImage。
2. 交互 canvas 默认直接显示这张 preview。

这意味着用户在可点击区域里看到的并不是纯原图，而是“原图 + 后端预先叠好的红色蒙层”。

### 4.2 推理服务预览图生成逻辑

推理服务在生成 segmentation preview 时，会主动构造一层 RGBA overlay：

1. 红色通道固定为 255。
2. alpha 对前景区域赋值 110。
3. 再把这层 overlay 与输入图进行 alpha composite。

因此 preview 本身就带有很强的红色视觉特征。

## 5. 设计目标

本轮修正的目标不是删除 segmentation preview，而是重新定义它的角色：

1. 保留 preview 作为方形 mask 空间的参考图。
2. 默认视觉底图改为原图，而不是红色 preview。
3. 仍然保证点击命中、轮廓绘制和徽标定位与 mask 坐标保持一致。

## 6. 实现思路

### 6.1 方形 mask 空间固定不变

分割 mask 来自推理输入空间，本质上是一个方形 letterbox 坐标系。这个坐标系不能直接丢掉，否则点击区域和轮廓都会偏移。

因此，本轮没有改 mask 坐标，而是继续把整个交互区保持为方形空间。

### 6.2 原图只作为绘制底图

交互 canvas 默认显示原图，但不是按原始宽高直接裁切，而是把原图以 BoxFit.contain 的方式绘制到整个方形画布中。这样：

1. 视觉上用户看到的是原图。
2. 几何上它与推理时的 letterbox 方式一致。
3. mask 仍然可以按整个方形画布进行映射。

### 6.3 轮廓与点击命中改为基于完整方形画布

此前 imageRect 是按当前显示图片的实际包围盒计算的。修正后，imageRect 直接使用整个方形 canvas，这样 mask 坐标、边界 path 和点击命中都会对齐到统一的 square mask space。

## 8. 实现结果

修正后的交互分割区默认表现为：

1. 背景是原图，而不是红色 preview。
2. 轮廓和编号仍然可点击。
3. 长按时只隐藏轮廓，方便直接查看纯原图。
4. 之前已经做过的轻量轮廓和低透明度选中态仍然保留。

## 9. 工程结论

这次问题可以作为一个典型案例写入论文或开发总结：

1. 用户看到的“效果没变”不一定是发布失败，也可能是展示链路里仍存在更上游的强视觉信号。
2. 当前端结果展示依赖模型预览图时，必须明确区分“坐标参考图”和“实际显示底图”。
3. 分割可视化的美观优化，不能只盯着 painter 的颜色参数，还要追踪底图来源。

## 10. 后续建议

如果后续还要继续优化分割交互体验，可继续沿两个方向细化：

1. 进一步降低选中态填充的不透明度，只保留柔和边缘强化。
2. 为小区域引入更智能的徽标避让策略，避免编号压住高关注食物细节。
