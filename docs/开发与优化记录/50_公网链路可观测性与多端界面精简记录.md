# 公网链路可观测性与多端界面精简记录

日期：2026-08-01

## 1. 本轮目标

1. 判断当前公网服务器的实际资源与 CPU 推理可行性。
2. 让上传任务可按 `taskId` 定位到入口、业务、Agent、推理和回写阶段。
3. 避免 Docker 日志无限增长。
4. 从首次用户视角删减 Web 与移动端重复说明和装饰性内容。

## 2. 当前服务器实测

| 项目 | 实测 |
| --- | --- |
| CPU | 4 vCPU，DO Premium Intel |
| 内存 | 8 GB，空闲态宿主约使用 2.5 GB |
| 磁盘 | 232 GiB，约使用 21 GiB |
| GPU | 无 |
| 容器空闲内存合计 | 约 1.9 GB |
| 最近真实任务耗时 | 约 9-13 秒 |

当前模型在公网环境使用 CPU。现有机器资源余量较大，下一台机器建议从 x86 `2 vCPU / 4 GB / 80 GB` 起步，并配置 2 GB swap。2 GB 内存不足以稳定承载 MySQL、RabbitMQ、MinIO、Chroma、Java 服务、Agent 和 PyTorch 推理的完整容器链路。

## 3. “任务很久没有结果”的实测结论

抽查最近四个真实任务后发现：业务端均在约 9-13 秒内收到结果并写回数据库，RabbitMQ 队列也没有堆积。与此同时，iPhone 微信内置浏览器对应的 Caddy 日志出现多次 HTTP/3 `context canceled` 与连接错误。

因此，本轮观察到的主要问题是前台状态轮询在移动浏览器切后台或连接切换时中断，造成“看起来仍在等待”；不是视觉模型长期卡住。

本轮前端改为：

1. 上传成功后直接进入 `/results/{taskId}`。
2. 使用串行 `setTimeout` 轮询，禁止异步请求重叠。
3. 页面重新回到前台时立即查询一次状态。
4. 任务详情处于 `PENDING` 时自动恢复轮询。
5. 移动端处理页显示已等待秒数和可复制的任务 ID。

## 4. 日志链路

| 阶段 | 服务 | 可定位内容 |
| --- | --- | --- |
| HTTPS 入口与状态轮询 | `gateway` / Caddy | URL、状态码、客户端连接异常 |
| 上传、入库、消息发布、结果回写 | `business` | `taskId`、业务状态和数据库更新时间 |
| Agent 消费与工作流 | `agent` | `taskId`、工作流总耗时、节点结果 |
| 分割推理 | `inference` | `taskId`、请求耗时、模型耗时、识别数量 |
| 队列 | `rabbitmq` | ready、unacked、consumer 数量 |

Agent 原先只配置了 `structlog`，而节点使用标准库 `logging`，导致 INFO 日志没有输出。本轮补齐标准日志配置，并在调用推理服务时通过 `X-Nutri-Task-Id` 传递任务 ID。

所有生产容器改为 Docker `json-file` 日志轮转：每文件 10 MB、保留 5 个文件。单服务上限约 50 MB，避免日志长期占满磁盘。

Caddy 访问日志额外删除 `X-Nutri-Access-Code`、`X-Nutri-Admin-Key` 和 `Cookie` 字段，避免授权信息进入日志。部署该规则时强制重建网关容器，使此前包含敏感请求头的旧容器日志随旧容器一并删除。

排查单个任务：

```bash
cd /opt/nutri-flow
bash scripts/trace-prod-task.sh <taskId> 2h
```

## 5. 用户视角审计结论

独立用户视角审计的高优先级问题：

1. Web 大幅品牌区和五张导航卡占满首屏，真正的“开始分析”被推后。
2. 上传结果追加在长页面底部，用户容易误以为任务没有完成。
3. 手机端授权后还有 onboarding，首次路径过长。
4. 处理状态、解释文字和提示卡重复。
5. 分割图像优先于热量、食物和建议，不符合普通用户阅读顺序。
6. 暖橙渐变、圆角卡片和装饰背景使用过多，信息层级显得臃肿。

## 6. 本轮界面收敛

Web：

1. 大块品牌导航改为紧凑顶栏，移动端使用固定底部导航。
2. 首页只保留核心价值、开始分析、拍摄要点和三个常用入口。
3. 上传页只保留图片、餐次、提交、错误状态和一个拍摄提示。
4. 结果页删除三张解释性摘要卡；建议正文提前，分割区域默认折叠。
5. 页面背景改为安静的中性色，主要卡片圆角统一为 8px。

移动端：

1. 已通过授权的用户直接进入登录或主页，不再强制 onboarding。
2. 首页删除装饰光斑和三段重复的新手提示。
3. 上传页合并重复标题与说明，只保留一条拍摄建议。
4. 处理页合并为一个状态区，显示等待秒数和任务 ID。
5. 分割区域默认折叠，优先展示本餐热量和食物摘要。

## 7. 后续验证
