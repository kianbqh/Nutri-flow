# Nutri-flow 开发任务分解与实现路线（单人版）

版本：v1.0  
适用阶段：功能规划与接口定义阶段（尚未进入大规模编码）

## 1. 说明

本文档按软件开发流程把工作拆解为可执行任务。由于项目为单人开发，不设置负责人字段，仅保留任务优先级、前置依赖、完成定义（DoD）。

## 2. 总体里程碑

1. M1 需求冻结与契约冻结
2. M2 前后端主链路打通（上传 -> 分析 -> 结果）
3. M3 结果页可交互（实例点击详情）
4. M4 目标画像与建议联动
5. M5 历史记录与异常恢复完善

## 3. 工作分解结构（WBS）

### 3.1 需求与设计

- T-001 对齐功能边界（仅热量管理）
  - 优先级：P0
  - 依赖：无
  - DoD：需求规格、用户故事、范围外清单一致。

- T-002 冻结接口字段口径
  - 优先级：P0
  - 依赖：T-001
  - DoD：接口文档 + OpenAPI 契约一致。

- T-003 冻结状态机与错误码
  - 优先级：P0
  - 依赖：T-002
  - DoD：前后端对 PENDING/COMPLETED/FAILED/TIMEOUT 处理一致。

### 3.2 移动端（Flutter）

- T-101 搭建页面骨架（Capture/Processing/Result/Profile/History）
  - 优先级：P0
  - 依赖：T-002
  - DoD：五个页面可导航，基础占位完成。

- T-102 上传与轮询链路
  - 优先级：P0
  - 依赖：T-101, T-003
  - DoD：可上传并轮询到结果或失败态。

- T-103 结果页实例交互
  - 优先级：P0
  - 依赖：T-102
  - DoD：点击实例可查看热量和营养简介。

- T-104 Profile 目标设定与保存
  - 优先级：P0
  - 依赖：T-101
  - DoD：目标、热量目标、禁忌可读写。

- T-105 History 分页查询
  - 优先级：P1
  - 依赖：T-102
  - DoD：分页加载、详情跳转可用。

- T-106 异常态体验完善
  - 优先级：P0
  - 依赖：T-102
  - DoD：失败、超时、断网均有提示与重试。

### 3.3 业务后端（Spring Boot）

- T-201 上传接口与任务持久化
  - 优先级：P0
  - 依赖：T-002
  - DoD：返回 taskId、状态 PENDING、任务可追踪。

- T-202 状态查询接口
  - 优先级：P0
  - 依赖：T-201
  - DoD：正确返回 PENDING/COMPLETED/FAILED。

- T-203 历史记录接口
  - 优先级：P1
  - 依赖：T-201
  - DoD：按 userId 分页返回摘要。

- T-204 用户画像接口
  - 优先级：P0
  - 依赖：T-002
  - DoD：GET/PUT 口径一致且可持久化。

- T-205 MQ 结果消费与幂等回写
  - 优先级：P0
  - 依赖：T-201
  - DoD：重复消费不造成脏数据；任务可从 PENDING 正确进入终态。

### 3.4 Agent 与推理服务

- T-301 分割调用节点稳定化
  - 优先级：P0
  - 依赖：T-002
  - DoD：输入输出字段和契约一致。

- T-302 热量解释最小闭环
  - 优先级：P0
  - 依赖：T-301
  - DoD：返回总热量、实例热量、简要建议。

- T-303 Agent 问答边界限制
  - 优先级：P1
  - 依赖：T-302
  - DoD：仅提出热量相关问题，不越界到诊疗。

### 3.5 测试与质量

- T-401 主链路 E2E
  - 优先级：P0
  - 依赖：T-102, T-202, T-301
  - DoD：上传 -> 轮询 -> 结果完成率达标。

- T-402 异常链路回归
  - 优先级：P0
  - 依赖：T-106, T-205
  - DoD：失败与超时场景可恢复。

- T-403 文档一致性检查
  - 优先级：P0
  - 依赖：所有文档
  - DoD：需求、接口、状态机、测试口径一致。

## 4. 当前阶段建议先做项

1. 先完成 T-001/T-002/T-003（需求、契约、状态机冻结）。
2. 同步推进 T-101/T-201/T-301（主链路最小切片）。
3. 最后收口 T-103/T-106/T-401（可演示可恢复）。

## 5. 完成定义（项目级）

1. 用户可独立完成一次完整分析。
2. 结果页可点击实例查看详情。
3. 用户画像更新影响后续建议。
4. 失败与超时均有恢复路径。
5. 所有文档与实现字段一致。
