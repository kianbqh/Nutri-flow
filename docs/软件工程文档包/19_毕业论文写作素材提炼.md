# Nutri-flow 毕业论文写作素材提炼

版本：v1.0

## 1. 文档目的

本文档用于把当前仓库中的稳定文档与开发留档，整理为“可直接进入毕业论文”的素材清单，减少后续写作阶段在资料筛选上的重复劳动。

## 2. 总体写作策略

对于当前课题“基于 Transformer 的实例分割技术研究和应用”，建议采用以下写作重心：

1. 软件工程过程是正文主轴，包括需求、架构、接口、状态机、测试、部署与版本治理。
2. 算法章节应强调“在产品约束下做可验证的模型优化”，而不是只堆叠实验名词。
3. 所有量化结果都应优先引用当前仓库中已经落盘验证的数字，不应凭回忆重写。
4. 所有技术名词、架构名称、算法名称、指标名称在正式论文中都应补齐外部文献引用。

## 4. 当前最有价值的论文论点

### 4.1 软件工程过程

1. 项目采用“稳定文档包 + 高频开发留档”的双层文档机制，兼顾冻结约束与快速迭代。
2. 需求、架构、接口、状态机、测试与实验 gate 构成了可追踪的软件工程闭环。

### 4.2 系统架构与实现

1. 系统采用多服务异步协同架构，降低前端等待并提升链路可追踪性。
2. `taskId` 与 workflow trace 让模型输出、消息链路和后端状态能被统一追踪。

### 4.3 算法与实验

1. 当前最优结果来自在既有 Transformer 主线上做温和调参，而不是频繁更换复杂结构。
2. Stage7S1 的提升说明 mild mask bias 有效。
3. Stage7S2、Stage7S3、Stage8S1 的负结论同样重要，因为它们帮助项目排除了错误方向。

### 4.4 产品交互与用户体验

1. 分割系统的产品价值不仅取决于 mIoU，还取决于结果页解释性、原图回补、视觉一致性与多端信息架构。
2. 个性化建议是否被感知到，取决于后端推理与前端展示的共同设计。

### 4.5 运行维护与部署

1. 健康检查、supervisor、孤儿进程治理和单消费者约束，是产品演示稳定性的关键条件。
2. 发布前检查不能只看“端口是否打开”，而应看真实健康检查与任务完成状态。
