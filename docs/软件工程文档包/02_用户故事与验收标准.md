# Nutri-flow 用户故事与验收标准

版本：v1.0

## 1. 目标用户画像

1. 轻量控卡用户：希望快速判断一餐热量是否超标。
2. 健身用户：关注热量和蛋白大致结构。
3. 学生用户：偏好操作简单、反馈直观。

## 2. 史诗（Epics）

1. E1 用户画像建立
2. E2 餐食分析闭环
3. E3 结果解释与引导
4. E4 历史回顾
5. E5 异常恢复与体验保障

## 3. 用户故事

### US-01 首次目标设定

作为新用户，我希望快速设置我的热量目标，这样系统能给我更匹配的提示。

验收标准：
1. 支持手动输入一句目标。
2. 支持 Agent 提问 3-5 个问题后生成画像。
3. 保存成功后可在 Profile 页面查看。

### US-02 上传餐食图片

作为用户，我希望可以拍照或从相册选择图片上传，这样我可以方便记录每餐。

验收标准：
1. 支持拍照和相册两种入口。
2. 可选择 mealType 并成功提交。
3. 返回 taskId 并进入处理页。

### US-03 处理状态可见

作为用户，我希望知道系统是否仍在分析，这样我不会误以为应用卡住。

验收标准：
1. 处理页显示状态和进度提示。
2. 支持 PENDING 到 COMPLETED 的状态更新。
3. 超时时出现明确提示和重试按钮。

### US-04 查看分割结果

作为用户，我希望看到图片中食物被分割出来，这样我能理解估算依据。

验收标准：
1. 结果页可显示分割图层（bbox 或 mask）。
2. 实例列表与图层项数量一致。
3. 小类别可根据策略跳过，但需有说明。

### US-05 查看单个食物详情

作为用户，我希望点击某个食物就能看到它的热量和简要营养信息，这样我能做更细粒度判断。

验收标准：
1. 点击实例可打开详情卡片。
2. 详情包括名称、热量估算、营养简析、简要介绍。
3. 所有数值标注为估算值。

### US-06 查看总热量与建议

作为用户，我希望看到整餐总热量和一句话建议，这样我知道是否需要调整。

验收标准：
1. 结果页展示总热量。
2. 提示文本与用户目标有关联。
3. 建议内容不超出热量管理范围。

### US-07 查看历史记录

作为用户，我希望回看过去分析记录，这样我可以观察饮食趋势。

验收标准：
1. 支持分页加载历史记录。
2. 列表显示 taskId、mealType、时间、状态、摘要。
3. 点击记录可进入详情页。

### US-08 异常恢复

作为用户，我希望在失败时有明确补救方案，这样不会中断使用。

验收标准：
1. 上传失败可重试。
2. 任务失败可重新发起分析。
3. 网络异常下有本地提示，不出现白屏或崩溃。

## 4. 故事优先级（MVP）

1. P0：US-01、US-02、US-03、US-04、US-05、US-06、US-08
2. P1：US-07
3. P2：更复杂的解释增强（例如更细分置信区间）

## 5. 用户旅程（简版）

1. Onboarding：输入目标或 Agent 问答。
2. Home：拍照/上传并提交。
3. Processing：查看任务状态。
4. Result：查看分割和热量详情。
5. History：回看历史并对比近期记录。
