# Local Startup Guide

Version: v1.1

This guide describes the recommended local startup path for the full
Nutri-flow stack on Windows PowerShell.

## Ports

| Service | Port |
|---|---:|
| Inference FastAPI | 18001 |
| Spring Boot business API | 18080 |
| MySQL | 3307 |
| Redis | 6379 |
| RabbitMQ AMQP | 5672 |
| RabbitMQ Console | 15672 |
| MinIO API | 9000 |
| MinIO Console | 9001 |
| Chroma | 8100 |

## Start

From the repository root:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/dev-up.ps1
```

If Docker infrastructure is already running:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/dev-up.ps1 -SkipDocker
```

The script starts or supervises:

- Docker infrastructure
- FastAPI inference service
- Spring Boot business service
- Python LangGraph agent consumer

Runtime logs and PID files are written under `.runtime/`.

## Health Check

```powershell
powershell -ExecutionPolicy Bypass -File scripts/dev-health.ps1
```

The stack is considered ready only when:

- inference health check passes
- business API check passes
- RabbitMQ task queue has at least one consumer

## Stop

```powershell
powershell -ExecutionPolicy Bypass -File scripts/dev-down.ps1
```

## Web Client

```powershell
cd nutri-web
npm run dev
```

The Vite dev server proxies `/api` requests to the business API.

## Flutter Client

```powershell
cd nutri-mobile
..\.tools\flutter_sdk_3.41.6\flutter\bin\flutter.bat devices
..\.tools\flutter_sdk_3.41.6\flutter\bin\flutter.bat run -d chrome
```

The mobile client selects a default API base URL by platform. Override it with:

```powershell
--dart-define=NUTRI_API_BASE=http://127.0.0.1:18080/api/v1
```

## Notes

- Do not rely on an already-open port alone; always run `scripts/dev-health.ps1`.
- The default local model is Stage7S1 Phase A through `NUTRI_SEG_CHECKPOINT`.
- Large local files such as model weights, datasets, toolchains, caches, and
  runtime logs are intentionally ignored by Git.
