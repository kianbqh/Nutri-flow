## 3. 推荐启动顺序

### 3.1 启动后端全链路

在仓库根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/dev-up.ps1
```

该脚本当前会完成以下动作：

1. 自动创建 `.runtime/logs`、`.runtime/pids`、`.runtime/supervisors`
2. 自动拉起 Docker 基础设施（除非显式传 `-SkipDocker`）
3. 启动并托管 inference 服务
4. 启动并托管 business 服务
5. 启动并托管 nutri-agent 消费者
6. 自动等待健康检查通过
7. 若发现服务已经健康但未被托管，会先接管再继续

### 3.2 检查后端是否真的可用

执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/dev-health.ps1
```

只有以下几项同时为 OK，才算后端链路可测试：

- 8001 inference 端口可连接
- 8080 business 端口可连接
- `GET /health` 成功
- `GET /api/v1/diet-logs` 成功
- RabbitMQ task queue 至少有 1 个 consumer

### 3.3 启动 Flutter

在 `nutri-mobile` 目录下执行：

```powershell
$env:PATH = 'g:\GraduationProj_Nutri-flow\Nutri-flow\.tools\flutter_sdk_3.41.6\flutter\bin;' + $env:PATH
flutter devices
flutter run -d web-server --web-hostname 127.0.0.1 --web-port 57717
```

当前已验证 `57717` 端口可访问。

如果需要浏览器调试，优先使用：

```powershell
flutter run -d chrome
```

或：

```powershell
flutter run -d edge
```

## 4. 关闭方式

后端链路统一关闭：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/dev-down.ps1
```

该脚本当前不仅会关闭 pid 文件对应的 supervisor，还会额外清理：

- `nutri-agent main.py` 孤儿 Python 进程
- 8001 监听进程
- 8080 监听进程

Flutter Web 若由终端 `flutter run` 启动，则在对应终端按 `q` 退出。

## 6. 当前注意事项

### 6.1 不要只看“端口开了”，要看健康检查

此前出现过的核心问题是：端口或子进程短暂存在，但 supervisor 已经失效，导致稍后服务退出后无人重启。

因此判断“启动成功”的标准不是“浏览器能打开一次”或“端口曾经监听过”，而是：

- `scripts/dev-health.ps1` 全绿
- `.runtime/pids` 中的 pid 对应进程仍然活着
- RabbitMQ task queue consumer 不为 0

### 6.2 Flutter 命令不要依赖系统 PATH

这台机器的 `flutter` 不在全局 PATH 中，之前 Flutter 起不来的直接原因就是这一点。

当前推荐做法：

- 从 VS Code 工作区直接运行，依赖 `.vscode/settings.json`
- 或在终端手动把本地 SDK 的 `bin` 加到 PATH 后再执行 Flutter 命令

### 6.3 Web 调试优先 Chrome / Edge

当前 `flutter devices` 识别的是 `Windows`、`Chrome`、`Edge`。如果走 Web 调试，优先 Chrome 或 Edge，避免把“浏览器问题”和“Flutter 服务没起来”混在一起。

### 6.4 后端先起，再起 Flutter

推荐顺序始终是：

1. `dev-up`
2. `dev-health`
3. `flutter run`

否则前端很容易在上传阶段直接报 `127.0.0.1:8080` 无法连接。

### 6.5 当前仓库对 C 盘占用的边界

当前已经本地化到仓库内的内容：

- Flutter SDK
- Maven 本地仓库
- Python 解释器使用 G 盘环境

但 Flutter / Dart 的部分第三方包缓存仍可能命中用户目录。如果后续需要“完全避免 C 盘写入”，还需要额外迁移 `PUB_CACHE`。

## 7. 最小自检流程

每次准备联调前，建议按下面顺序执行一次：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/dev-down.ps1
powershell -ExecutionPolicy Bypass -File scripts/dev-up.ps1
powershell -ExecutionPolicy Bypass -File scripts/dev-health.ps1
```

然后启动 Flutter：

```powershell
Set-Location nutri-mobile
$env:PATH = 'g:\GraduationProj_Nutri-flow\Nutri-flow\.tools\flutter_sdk_3.41.6\flutter\bin;' + $env:PATH
flutter run -d web-server --web-hostname 127.0.0.1 --web-port 57717
```

最后至少确认一次：

- 页面可以打开
- 上传接口可达
- 结果页能返回 `COMPLETED`
- 上传完成后再跑一次 `scripts/dev-health.ps1`，确认服务未掉线

## 8. 一句话结论

当前仓库已经具备稳定的本地启动路径：后端使用 `dev-up / dev-health / dev-down` 管理，Flutter 使用仓库内置 SDK 启动；只要按“后端先全绿，再起 Flutter”的顺序执行，现阶段可以进入正常联调与测试。
