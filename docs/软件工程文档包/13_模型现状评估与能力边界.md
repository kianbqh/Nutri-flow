# Nutri-flow 模型现状评估与能力边界（开发前基线）

版本：v1.0  
来源：stage3 结果、stage6 系列 full-val 结果、stage6s6 报告与评估文件

## 1. 当前模型主线结论

1. 主干架构已落地：Swin Transformer + BiFPN + Coordinate Attention。
2. 分辨率主线结论：512 路线在多轮 full-val 中表现更优。
3. 训练策略结论：阶段门控 + 低学习率精修，比单纯长训更稳定。

## 2. 关键指标快照（full-val）

1. Stage3 Tiny：mIoU 0.0933（224 基线阶段）。
2. Stage6S3（512 from 384best）：mIoU 0.310680，非背景有效类 96。
3. Stage6S4（512 100ep）：mIoU 0.313333，非背景有效类 97。
4. Stage6S5 PhaseA（512 70ep）：mIoU 0.316562，非背景有效类 96。
5. Stage6S6 PhaseC（512 20ep）：mIoU 0.316991，非背景有效类 98。

结论：当前可作为“产品可用基线”的最佳结果是 Stage6S6 PhaseC。

## 3. 能力边界（对产品侧）

### 3.1 可以支持

1. 主流餐食场景的实例分割与热量粗估。
2. 结果页按实例点击查看详情。
3. 给出总热量和简短解释文案。

### 3.2 需要谨慎

1. 小体积、遮挡严重、边界模糊食物类别。
2. 超复杂混合菜品的精细份量估算。
3. 长尾类别稳定性（类间表现不均衡）。

### 3.3 暂不承诺

1. 医疗级精度与诊断结论。
2. 任意光照与极端拍摄角度下的一致高精度。

## 4. 对产品文案与交互的要求

1. 所有热量显示必须标注为“估算值”。
2. 低置信度结果应展示提示并建议补拍。
3. 不稳定小类可降级隐藏，优先展示主要食物。

## 5. 开发阶段建议

1. 先围绕最佳 checkpoint 完成端到端闭环，不在当前阶段新增复杂模型结构。
2. 产品验收优先看“可用性 + 可解释性 + 稳定返回”，而非盲目追求单点指标。
3. 若后续做论文强化，再补模块消融与公开对比实验。
