# Nutri-flow 接口文档

版本：v1.0  
协议：HTTP + JSON（上传接口为 multipart/form-data）

## 1. 通用约定

1. Base URL（业务后端）：`/api/v1`
2. 认证（MVP 阶段）：通过请求头 `X-User-Id`
3. 时间格式：ISO-8601
4. 枚举：
   - mealType: BREAKFAST | LUNCH | DINNER | SNACK
   - status: PENDING | COMPLETED | FAILED

## 2. 用户画像接口

### 2.1 获取用户画像

- 方法：GET
- 路径：`/users/{userId}/profile`

响应示例：

```json
{
  "userId": 1,
  "healthGoal": "WEIGHT_LOSS",
  "dailyCalorieTarget": 1800,
  "dietaryRestrictions": ["high_sugar"]
}
```

### 2.2 更新用户画像

- 方法：PUT
- 路径：`/users/{userId}/profile`

请求示例：

```json
{
  "healthGoal": "WEIGHT_LOSS",
  "dailyCalorieTarget": 1800,
  "dietaryRestrictions": ["high_sugar"]
}
```

响应示例：

```json
{
  "userId": 1,
  "healthGoal": "WEIGHT_LOSS",
  "dailyCalorieTarget": 1800,
  "dietaryRestrictions": ["high_sugar"]
}
```

## 3. 饮食分析接口

### 3.1 上传餐食图片

- 方法：POST
- 路径：`/diet-logs/upload`
- Header：`X-User-Id: 1`
- Content-Type：multipart/form-data
- 字段：
  - file: 图片文件
  - mealType: BREAKFAST | LUNCH | DINNER | SNACK

响应示例：

```json
{
  "taskId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "ossKey": "meals/user_001/lunch_20260327.jpg",
  "status": "PENDING"
}
```

## 4. MQ 任务契约（业务后端 -> Agent）

契约来源：`contracts/image_analysis_task.schema.json`

必须字段：

1. taskId (uuid)
2. userId (string)
3. imageUrl (uri)
4. ossKey (string)
5. mealType (enum)
6. createdAt (date-time)

可选字段：

1. userContext
   - dietaryRestrictions: string[]
   - healthGoal: WEIGHT_LOSS | MUSCLE_GAIN | MAINTENANCE | GENERAL_HEALTH
   - dailyCalorieTarget: int
2. callbackRoutingKey: string

## 5. 错误码建议

1. INVALID_PARAM：参数不合法
2. UNSUPPORTED_FILE_TYPE：文件类型不支持
3. TASK_NOT_FOUND：任务不存在
4. MODEL_INFERENCE_ERROR：模型推理失败
5. MQ_PUBLISH_ERROR：消息投递失败
6. INTERNAL_ERROR：服务内部错误

## 6. 版本与兼容策略

1. 接口前缀使用 `/api/v1`。
2. 新增字段应向后兼容，不删除旧字段。
3. 重大变更需升级至 v2 并维护迁移说明。
