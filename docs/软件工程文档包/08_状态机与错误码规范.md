# Nutri-flow 状态机与错误码规范

版本：v1.0

## 1. 目标

统一任务状态流转、前后端行为和错误码语义，避免出现状态不一致、前端卡死、错误不可恢复等问题。

## 2. 任务状态定义

后端状态：

1. PENDING：任务已创建，等待或正在分析。
2. COMPLETED：任务成功完成，包含 analysisResult。
3. FAILED：任务失败，包含错误信息。

前端扩展状态：

1. TIMEOUT：前端轮询超时（展示态），可重试或稍后查询。

## 3. 状态流转规则

1. INIT -> PENDING：上传成功返回 taskId。
2. PENDING -> COMPLETED：结果回写成功。
3. PENDING -> FAILED：分析或回写失败。
4. PENDING -> TIMEOUT（前端展示态）：超过轮询阈值仍无终态。
5. TIMEOUT -> PENDING：用户手动重查时可恢复轮询。

禁止流转：

1. COMPLETED -> PENDING
2. FAILED -> COMPLETED（除非生成新 taskId 的重试任务）

## 4. 前端行为规范

1. PENDING：显示处理中与可取消返回。
2. COMPLETED：展示结果页。
3. FAILED：展示失败原因与一键重试。
4. TIMEOUT：提示稍后重试，保留 taskId 查询入口。

## 5. 后端行为规范

1. 上传接口必须返回 taskId 和 PENDING。
2. 状态查询接口必须幂等。
3. 结果回写按 taskId 幂等处理，避免重复写入污染。
4. 失败必须带 machine-readable 错误码。

## 6. 错误码规范

### 6.1 通用

1. INVALID_PARAM：参数不合法
2. UNAUTHORIZED：鉴权失败
3. INTERNAL_ERROR：内部错误

### 6.2 上传与任务

1. UNSUPPORTED_FILE_TYPE：图片格式不支持
2. FILE_TOO_LARGE：文件过大
3. OSS_UPLOAD_ERROR：对象存储上传失败
4. MQ_PUBLISH_ERROR：消息投递失败
5. TASK_NOT_FOUND：任务不存在

### 6.3 推理与Agent

1. MODEL_INFERENCE_ERROR：模型推理失败
2. EMPTY_DETECTION：未检测到有效食物
3. ADVICE_GENERATION_ERROR：建议生成失败
4. CALLBACK_PUBLISH_ERROR：结果回传失败

### 6.4 数据与一致性

1. RESULT_PARSE_ERROR：结果解析失败
2. RESULT_WRITE_CONFLICT：结果回写冲突
3. IDEMPOTENCY_VIOLATION：幂等键冲突

## 7. 错误响应结构

```json
{
  "code": "MODEL_INFERENCE_ERROR",
  "message": "模型推理失败，请稍后重试",
  "taskId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "retryable": true,
  "traceId": "abc-123"
}
```

字段说明：

1. code：稳定错误码。
2. message：可直接给用户展示的文案。
3. taskId：可选，便于问题定位。
4. retryable：是否建议重试。
5. traceId：链路追踪 ID。

## 8. 超时策略建议

1. 前端轮询间隔：2-3 秒。
2. 超时阈值：60-90 秒（按环境可配置）。
3. TIMEOUT 后不丢任务，允许继续查询。

## 9. 验收检查清单

1. 状态流转不出现逆向跳转。
2. 所有失败响应都带 code。
3. 前端能区分 FAILED 与 TIMEOUT。
4. 重试后产生新 taskId，旧任务不被覆盖。
