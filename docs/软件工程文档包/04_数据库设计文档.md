# Nutri-flow 数据库设计文档

版本：v1.0

## 1. 设计目标

1. 支撑用户画像、任务状态、结果历史查询。
2. 满足主流程读写性能与可追溯要求。
3. 便于后续扩展（例如建议版本、模型版本）。

## 2. 数据域划分

1. 用户域：用户基础信息与健康画像。
2. 任务域：上传任务、状态流转、错误信息。
3. 结果域：分割结果、营养估算、建议文本。
4. 历史域：用于列表展示的摘要字段。

## 3. 逻辑模型

### 3.1 user_profile

- user_id (PK, bigint)
- health_goal (varchar)
- daily_calorie_target (int)
- dietary_restrictions (json)
- created_at (datetime)
- updated_at (datetime)

说明：存储用户目标画像，供上传任务时注入 userContext。

### 3.2 diet_log_task

- task_id (PK, varchar/uuid)
- user_id (bigint, index)
- meal_type (varchar)
- oss_key (varchar)
- image_url (varchar)
- status (varchar)  // PENDING, COMPLETED, FAILED
- failure_reason (varchar, nullable)
- created_at (datetime, index)
- updated_at (datetime)
- callback_routing_key (varchar, nullable)

说明：任务主表，记录全链路状态。

### 3.3 diet_log_result

- id (PK, bigint)
- task_id (FK -> diet_log_task.task_id, unique)
- total_calories (decimal(10,2), nullable)
- advice_report (text, nullable)
- confidence_level (varchar, nullable)
- kcal_range_min (decimal(10,2), nullable)
- kcal_range_max (decimal(10,2), nullable)
- model_version (varchar, nullable)
- created_at (datetime)
- updated_at (datetime)

说明：任务结果主信息，和任务表一对一。

### 3.4 diet_log_detected_item

- id (PK, bigint)
- task_id (FK -> diet_log_task.task_id, index)
- class_id (int)
- class_name (varchar)
- display_name (varchar)
- calories (decimal(10,2), nullable)
- protein_g (decimal(10,2), nullable)
- fat_g (decimal(10,2), nullable)
- carbs_g (decimal(10,2), nullable)
- weight_g (decimal(10,2), nullable)
- confidence_score (decimal(6,4), nullable)
- mask_rle (longtext, nullable)
- bbox_json (json, nullable)
- introduction (text, nullable)
- created_at (datetime)

说明：实例明细，用于结果页点击查看。

## 4. 索引设计

1. idx_task_user_created：diet_log_task(user_id, created_at desc)
2. idx_task_status：diet_log_task(status)
3. idx_item_task：diet_log_detected_item(task_id)

## 5. 状态机设计

1. 初始状态：PENDING
2. 成功终态：COMPLETED
3. 失败终态：FAILED
4. TIMEOUT 为前端展示状态，不回写数据库终态（可选扩展为超时字段）

## 6. 数据一致性策略

1. 任务创建与 MQ 投递应保证至少一次语义。
2. 结果回写需幂等（按 task_id 唯一）。
3. 消费重复消息时，已完成任务应安全忽略或更新不冲突字段。

## 7. 历史查询模型（接口视图）

建议从 task + result 聚合生成摘要：

- taskId
- mealType
- loggedAt
- status
- detectedItemsCount
- adviceReport

## 8. 数据生命周期

1. 原始图像可设定过期清理策略（节省存储成本）。
2. 任务与结果至少保留用于课程答辩周期的数据。
3. 日志长期归档时应脱敏。

## 9. 样例 DDL（MySQL 简版）

```sql
CREATE TABLE user_profile (
  user_id BIGINT PRIMARY KEY,
  health_goal VARCHAR(64) NOT NULL,
  daily_calorie_target INT,
  dietary_restrictions JSON,
  created_at DATETIME NOT NULL,
  updated_at DATETIME NOT NULL
);

CREATE TABLE diet_log_task (
  task_id VARCHAR(64) PRIMARY KEY,
  user_id BIGINT NOT NULL,
  meal_type VARCHAR(32) NOT NULL,
  oss_key VARCHAR(255) NOT NULL,
  image_url VARCHAR(1024) NOT NULL,
  status VARCHAR(32) NOT NULL,
  failure_reason VARCHAR(255),
  created_at DATETIME NOT NULL,
  updated_at DATETIME NOT NULL,
  callback_routing_key VARCHAR(128),
  INDEX idx_task_user_created (user_id, created_at DESC),
  INDEX idx_task_status (status)
);

CREATE TABLE diet_log_result (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  task_id VARCHAR(64) NOT NULL UNIQUE,
  total_calories DECIMAL(10,2),
  advice_report TEXT,
  confidence_level VARCHAR(32),
  kcal_range_min DECIMAL(10,2),
  kcal_range_max DECIMAL(10,2),
  model_version VARCHAR(64),
  created_at DATETIME NOT NULL,
  updated_at DATETIME NOT NULL,
  CONSTRAINT fk_result_task FOREIGN KEY (task_id) REFERENCES diet_log_task(task_id)
);

CREATE TABLE diet_log_detected_item (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  task_id VARCHAR(64) NOT NULL,
  class_id INT,
  class_name VARCHAR(128),
  display_name VARCHAR(128),
  calories DECIMAL(10,2),
  protein_g DECIMAL(10,2),
  fat_g DECIMAL(10,2),
  carbs_g DECIMAL(10,2),
  weight_g DECIMAL(10,2),
  confidence_score DECIMAL(6,4),
  mask_rle LONGTEXT,
  bbox_json JSON,
  introduction TEXT,
  created_at DATETIME NOT NULL,
  INDEX idx_item_task (task_id),
  CONSTRAINT fk_item_task FOREIGN KEY (task_id) REFERENCES diet_log_task(task_id)
);
```
