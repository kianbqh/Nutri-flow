# Nutri-flow 需求规格说明书（SRS）

版本：v1.0  
适用范围：移动端 MVP + 后端核心链路  
依据文档：项目统一总计划、Flutter MVP Spec、E2E 测试指南、任务契约

## 1. 引言

### 1.1 目的

本文档用于明确 Nutri-flow 的产品目标、功能需求、非功能需求和约束条件，为后续系统设计、开发、测试和答辩材料提供统一基线。

### 1.2 项目背景

Nutri-flow 是一个面向 C 端的移动应用，核心是“食物实例分割 + 热量估算”。用户通过拍照上传餐食图片，系统异步完成分析并返回可交互结果。

### 1.3 术语定义

- 实例分割：将图像中不同食物对象像素级分离。
- 任务 ID（taskId）：一次分析任务的全链路唯一标识。
- 用户画像：用户健康目标、热量目标、饮食禁忌等信息集合。
- 估算值：非医学诊断、存在误差区间的营养结果。

## 2. 产品范围

### 2.1 业务目标

1. 提供可用的餐食热量估算闭环。
2. 将实例分割能力可视化并可交互查看实例详情。
3. 支持基于用户目标的轻量健康提示。

### 2.2 范围内

1. 用户目标设定（手填或 Agent 问答）。
2. 拍照/上传、异步分析、状态轮询。
3. 分割结果展示与实例点击查看详情。
4. 总热量估算与简要营养分析。
5. 历史记录查询。

### 2.3 范围外

1. 医疗诊断与治疗建议。
2. 复杂社交体系。
3. 开放域长对话健康问诊。

## 3. 角色与使用场景

### 3.1 角色

1. 普通用户：上传图片并查看热量分析。
2. 运营/研发：维护系统稳定性与模型效果。
3. 导师/评审：验证系统工程闭环与可解释性。

### 3.2 关键场景

1. 用户首次配置目标后进行首次拍照分析。
2. 用户重复上传多餐记录并查看历史。
3. 网络波动、任务失败、超时场景下的恢复操作。

## 4. 功能性需求

### FR-01 用户目标设定

- 系统应支持用户手动输入目标。
- 系统应支持 Agent 在 3-5 个问题内完成目标采集。
- 系统应保存并可更新用户画像。

### FR-02 图片上传与任务创建

- 系统应支持相机拍照或相册上传。
- 系统应在上传后返回 taskId 和初始状态 PENDING。
- 系统应记录 mealType（早餐/午餐/晚餐/加餐）。

### FR-03 异步分析与状态查询

- 系统应支持任务异步处理。
- 系统应支持状态查询：PENDING、COMPLETED、FAILED。
- 前端应支持 TIMEOUT 逻辑并可重试。

### FR-04 分割结果与详情

- 系统应返回分割结果与检测实例集合。
- 前端应支持点击单个实例查看详情。
- 详情至少包含食物名称、估算热量、简要营养、简介。

### FR-05 热量汇总与建议

- 系统应计算并返回本餐总热量估算。
- 系统应生成与用户目标相关的建议文本。
- 建议内容必须限定在热量管理范畴。

### FR-06 历史记录

- 系统应提供按用户分页查询历史记录接口。
- 历史记录应包含 taskId、mealType、时间、状态、简要结果。

### FR-07 异常处理

- 上传失败需提示原因与重试入口。
- 超时需提示系统繁忙并允许再次提交。
- 低置信度结果应带提示标识，避免误导。

## 5. 非功能需求

### NFR-01 性能

1. 分析平均时延目标：15 秒以内（本地/近线环境）。
2. 支持基础并发下稳定处理，不出现任务丢失。

### NFR-02 可用性

1. 用户可在无指导下完成一次完整分析。
2. 错误提示可理解且可恢复。

### NFR-03 可靠性

1. taskId 在全链路唯一且可追踪。
2. 状态流转必须一致，避免“卡死在 PENDING”。

### NFR-04 安全与隐私

1. 用户信息最小化采集。
2. 日志需脱敏，不记录不必要隐私内容。

### NFR-05 可维护性

1. 文档化接口契约。
2. 模块边界清晰，便于独立迭代。

## 6. 数据需求

1. 分析任务契约应包含：taskId、userId、imageUrl、ossKey、mealType、createdAt。
2. 支持 userContext（healthGoal、dailyCalorieTarget、dietaryRestrictions）透传。
3. 结果需支持前端实例明细展示字段。

## 7. 约束条件

1. 移动端优先（Flutter）。
2. 系统部署以低成本为目标。
3. 结果必须标注“估算值”。
4. 不提供医疗建议。

## 8. 验收准则

1. 主流程可通：目标设定 -> 上传 -> 分析 -> 结果 -> 历史。
2. 结果页可点击实例并展示正确详情。
3. Profile 更新会影响后续建议内容。
4. 异常场景均有可恢复路径。
