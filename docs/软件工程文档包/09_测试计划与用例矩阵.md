# Nutri-flow 手动测试用例矩阵与执行记录表

版本：v1.1

## 1. 文档目标

本文档用于支撑毕业论文阶段的手动测试执行与附录整理。与早期“测试规划”为主的版本不同，当前版本重点服务以下场景：

1. 统一整理移动端与网页端的手动测试用例。
2. 为论文第六章和附录 A 提供可直接填写的执行结果表。
3. 让后续截图编号、执行日期和备注可以按统一格式补录。

## 2. 当前测试策略

本阶段采用“手动测试 + 运行验证”为主的策略，不展开复杂自动化测试建设。其核心原因在于：当前毕业设计已进入收口与答辩准备阶段，优先目标是验证主链路可用、双端页面可演示、运行证据完整，而不是建设高成本的自动化回归体系。

当前测试策略包括以下三部分：

1. 移动端与网页端主流程手动测试。
2. 关键异常场景手动测试。
3. 本地/近线环境下的健康检查、近线冒烟任务与构建验证。

## 3. 测试范围

1. 用户画像配置
2. 图片上传与任务创建
3. 状态轮询与终态展示
4. 结果页实例交互
5. 历史记录分页与详情回看
6. 异常恢复与降级

## 4. 准入条件与完成标准

准入条件：

1. 接口契约与页面结构已基本冻结。
2. 测试环境可正常启动。
3. 移动端与网页端可进入主要功能页面。

完成标准：

1. P0 用例手动执行结果全部达到预期。
2. P1 用例整体达到预期。
3. 无阻断级缺陷。
4. 健康检查、近线冒烟任务和网页前端构建验证通过。

## 7. 缺陷分级建议

1. S1 阻断：主链路不可用、任务不可完成。
2. S2 严重：核心功能可用但错误率高或结果错误。
3. S3 一般：非核心场景异常或体验问题。
4. S4 轻微：文案、样式等低风险问题。

## 8. 测试数据建议

1. 常见菜品样本：米饭、面条、肉类、蔬菜。
2. 复杂场景样本：混合菜、遮挡、低光照。
3. 异常样本：空图、模糊图、非食物图。

## 9. 截图与附录对应建议

1. 移动端与网页端的主流程截图统一编号后放入附录 A。
2. 运行验证截图与近线冒烟任务结果统一放入附录 D。
3. 每个用例至少保留一个可回溯截图编号，便于答辩时快速对应到执行结论。
