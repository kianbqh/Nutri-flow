# Nutri-flow 测试计划与用例矩阵（规划阶段）

版本：v1.0

## 1. 文档目标

在未大规模开发前，先定义测试策略与用例矩阵，保证后续开发时“功能、接口、状态、异常”都有对应验证项。

## 2. 测试范围

1. 用户画像配置
2. 图片上传与任务创建
3. 状态轮询与终态展示
4. 结果页实例交互
5. 历史记录分页
6. 异常恢复与降级

## 3. 测试分层

1. 接口测试：参数、响应结构、错误码。
2. 集成测试：后端 + MQ + Agent + 推理服务协同。
3. E2E 测试：从移动端操作到结果展示完整链路。
4. 回归测试：核心路径和高风险异常场景。

## 4. 入口/退出准则

入口准则：

1. 接口契约冻结。
2. 状态机规范冻结。
3. 测试环境可启动。

退出准则：

1. P0 用例通过率达到目标。
2. 无阻断级缺陷。
3. 主链路成功率与时延满足目标区间。

## 6. 缺陷分级建议

1. S1 阻断：主链路不可用、任务不可完成。
2. S2 严重：核心功能可用但错误率高或结果错误。
3. S3 一般：非核心场景异常或体验问题。
4. S4 轻微：文案、样式等低风险问题。

## 7. 测试数据建议

1. 常见菜品样本：米饭、面条、肉类、蔬菜。
2. 复杂场景样本：混合菜、遮挡、低光照。
3. 异常样本：空图、模糊图、非食物图。

## 8. 可追踪性

每个用例应映射到需求编号（FR）和接口路径，便于答辩时展示“需求-设计-测试”闭环。
